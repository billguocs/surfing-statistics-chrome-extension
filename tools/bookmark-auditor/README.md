# 书签体检 · Bookmark Auditor

一个只在你本机运行的 Chrome 扩展：把书签里的链接扫一遍，列出失效项，预览后批量删除，删错了还能撤销。被 301/302 跳到新地址的链接会单独标成「可更新」，可以一键把书签改成新网址。

## 安装

1. 打开 `chrome://extensions/`，右上角开启「开发者模式」。
2. 点「加载已解压的扩展程序」，选择本目录（`tools/bookmark-auditor`）。
3. 把工具栏上的「书签体检」固定到显眼位置，点击即在新标签页打开面板。

首次加载时 Chrome 会提示它「读取和更改您的所有网站数据」——这是跨站探测链接状态所必需的（`host_permissions`）。扩展没有内容脚本，不注入页面，不联网上传任何数据。

## 用法 A：扫描全部书签

1. 打开面板 → 「扫描全部书签」→「开始扫描」。
2. 检测使用浏览器自己的网络栈，因此会自动带上你当前的代理、VPN、登录态。
3. 默认并发 8、超时 10 秒；书签多时可以先「停止」，已检测的结果会保留。
4. 结果里默认勾选「失效」项，确认后点「删除选中」。
5. 检测中被跳转到新地址的条目会显示「可更新」徽章：点行尾的「用新网址」只改这一条，或勾选后点「更新网址 (N)」批量改。标题和文件夹保持不变，旧网址会备份，可用「撤销」还原。

## 用法 B：用外部清单清理

配合本目录的 `check-bookmarks.mjs`（Node 18+，在命令行里读 Chrome 的 Bookmarks 文件并探测）：

```powershell
cd tools/bookmark-auditor
node check-bookmarks.mjs              # 默认读 Default 配置，输出到当前目录
node check-bookmarks.mjs --profile "Profile 1" --conc 8 --timeout 10000
```

也可以用任何方式得到的失效清单：

1. 切到「粘贴 / 导入清单」，粘贴每行一个网址，或直接导入脚本生成的 `dead-urls.txt` / CSV 文件。
2. 「按清单匹配」：不联网，把清单里的网址直接标为失效（适合已经用脚本判定过的清单）。
3. 「匹配并重新检测」：再请求一次，确认清单是否仍然失效。
4. 勾选后删除。

中途停止复检时，尚未收到结果的链接标为「未检测」，默认不勾选。

脚本只读 Bookmarks 文件，输出 `bookmark-report.csv`、`dead-urls.txt` 和 `moved-urls.csv`（跳转后建议更新的网址）。它不走浏览器，所以**不会自动使用系统代理**；需要代理时用 Node 24 并设置 `NODE_USE_ENV_PROXY=1`，或直接用扩展的「扫描全部书签」（走浏览器网络栈）。脚本不能改书签，`moved-urls.csv` 里的条目需要回到扩展里用「可更新」筛选后一键更新。

匹配是按 URL 精确匹配的（大小写、末尾斜杠都算不同）。清单里没匹配到的网址会单独列出来，通常意味着书签已被删、或不在当前浏览器配置文件里。

## 判定规则

| 状态 | 依据 | 默认勾选 |
| --- | --- | --- |
| 失效 | HTTP 404 / 410，或来自外部清单 | 是 |
| 无法连接 | 请求异常（DNS 失败、连接被拒、TLS 错误、超时） | 否 |
| 待确认 | 401 / 403 / 429 / 451 / 5xx / 其它 4xx | 否 |
| 正常 | 2xx | 否 |
| 可更新 | 不改变上面的状态，额外标记：跳转后的最终地址与原地址不同（忽略末尾斜杠和 #片段） | 否 |
| 未检测 | 扫描被中途停止 | 否 |

「可更新」只在跳转后的页面能正常返回（正常 / 待确认）时才标记，避免把书签改到死链上；跳转后 404 的仍然记为「失效」。「可更新」是叠加标记，不是独立状态，所以一条书签可以同时是「可更新 + 正常」。

浏览器无法区分「域名不存在」「被墙」「断网」这几种请求异常，所以一律归入「无法连接」而不是「失效」，避免误删。想要 DNS 级别的精确判定，用本目录的 `check-bookmarks.mjs`，它的报告会把 `ENOTFOUND`、`ECONNREFUSED` 等错误码单独列出来。

## 删除、更新网址与撤销

- 删除前会把待删条目（标题、URL、原父文件夹）写入扩展的 `chrome.storage.local`，面板底部会出现「撤销上一次删除」。
- 撤销会尽量恢复到原来的文件夹；如果原文件夹已被删（例如顺带清理了空文件夹），则恢复到「其他书签」根下。
- 更新网址前会备份每条书签的旧网址，面板底部出现「撤销上一次网址更新」，撤销时逐条把网址改回去。
- 新网址如果已经存在于书签中（或本次更新后彼此重复），确认框会提示会产生重复条目；扩展不会自动合并或去重。
- 只保留**最近一次**成功变更（删除或更新，二选一）的备份。部分失败时，撤销仅恢复已经变更的条目。撤销失败的条目可以重试。
- 勾选「删除后清理空文件夹」会在删除完成后，自底向上移除变空的文件夹；书签栏、其他书签、移动设备书签等系统文件夹受保护。
- 如果 Chrome 开了同步，删除和更新都会同步到登录同一账号的其它设备。动手前最好用 `chrome://bookmarks` → ⋮ → 导出书签 做一份完整备份。

## 已知限制

- **跳转不等于搬家**：短链、登录跳转、地域跳转或跟踪参数都可能让最终地址变化，扩展只把「跳转 → 新地址」摆出来，是否更新由你逐条确认。
- **软失效**：域名过期后被停放、站点改版后 200 返回无关内容的，检测不出来，仍需人工看一眼。
- **需要登录的页面**：默认不带 Cookie 时通常返回 200 或 403；勾选「携带 Cookie」会更准，但也会以你的登录态发起请求。
- **限流**：并发太高会被目标站点 429，此时调低并发即可。
- **https 证书错误**：会和 DNS 失败一样归入「无法连接」。
