# v2.2 设计：无媒体且系统空闲时暂停计时（"没在看"检测）

> 日期：2026-09-07
> 状态：已与用户确认，待审阅
> 目标版本：v2.2（manifest 版本 2.1.0 → 2.2.0）

## 1. 背景与问题

当前计时只由 `document.visibilityState` + 前台 tab 驱动：只要某 tab 是前台且页面可见，就持续累计时长——**无论用户是否真的在看**。这导致"人走开/切到别的程序，浏览器停在某个普通网页"时，该站点时长仍在虚增，统计失真。

目标：当「当前前台页面既不播放视频也不播放音频、且用户处于系统空闲」时，视为用户未在浏览该页面，**暂停计时**，从发现时刻起不再累计。

## 2. 已确认的决策

| 维度 | 决策 |
|------|------|
| 检测机制 | **浏览器 Idle 检测**（`chrome.idle` 系统级）+ 复用 1 分钟 alarm 轮询（方案 A） |
| 媒体豁免判定 | **播放中即算（含静音）**：`!paused && !ended` 即视为"在消费媒体"，豁免空闲暂停 |
| 空闲信号源 | `chrome.idle.queryState` 系统级（无键盘/鼠标输入即算；锁屏也计入） |
| 时长口径 | **从发现时刻停**（`pauseSession(now)`），不回溯、不删已累计 |
| 默认开关 | **默认开启**（开箱生效，可选项里关闭） |
| 空闲阈值 | **3 分钟**（options 提供 1/3/5 分钟下拉，可配） |
| 实现方案 | **方案 A**：复用现有 `behavior-check`（periodInMinutes:1）alarm |
| 设计文档位置 | `docs/` 目录（用户指定） |

## 3. 判定规则（一句话）

> 默认开启；仅当「正在计时的前台 session」被检测到「系统空闲 ≥3 分钟（含锁屏）**且**该页面无媒体在播放（含静音）」时，把该 session 从发现时刻暂停。

### 3.1 触发点

复用现有 `behavior-check` alarm（1 分钟）在 `evaluateBehaviorRules()` 末尾新增一步 `evaluatePresence()`：

1. 取当前 `activeSession`；若 `!isRunning` → return（已暂停，不在计时，无需处理）。
2. 用 `chrome.tabs.get` 校验 session.tabId 仍存在且 URL 一致；失败 → 视为不可达，跳过本轮（保守）。
3. 向该 tab `tabs.sendMessage` 询问媒体播放状态；超时/无响应/抛错 → 容错为"无媒体"。
4. `chrome.idle.queryState(180)` 查询系统空闲（阈值 = presenceConfig.idleThresholdMinutes × 60）。
5. 若返回 `idle` 或 `locked` **且** 无媒体播放 → `pauseSession(now)`。

### 3.2 恢复

idle 判定"恢复活跃"（`active`）**不**在 tick 里直接 resume —— 用户在别的程序打字也会让系统变 active，但那不代表他在看本页。恢复来自两类确定性信号：

1. **页面级交互（同页回看）**：content.js 在页面可见时监听用户输入（点击/滚轮/键盘/触摸，15s 节流）发 `PAGE_ACTIVE`，background 的 `resumeSessionOnInteraction` 仅当该 tab 恰为被暂停的当前 session 时重新置为 running（`startedAt` 重置为此刻，暂停空档不计入）。
2. **导航/焦点类事件**：`tabs.onActivated` / `tabs.onUpdated` / `windows.onFocusChanged` / content 的 `PAGE_VISIBLE`，由既有逻辑 `resumeOrReplaceSession` 处理。

两者都只会在"该页面确实是当前被追踪的 session"时恢复，避免把在别的程序打字误判为本页活跃。

## 4. 媒体豁免语义

- 有 `<video>`/`<audio>` 处于播放中（`!paused && !ended`，**含静音**）→ 视为用户在消费内容，即使系统 idle 也不暂停。
- 页面停止播放 → 下个检查点若仍系统 idle 才暂停。
- **取舍（已确认）**：静音播放的 YouTube 而人离开时，此页仍会计时。这是"含静音豁免"方案比"有声才算"更宽松的固有边界。

## 5. 存储键：`presenceConfig`（新增，local 区）

```js
{
  enabled: true,            // 默认开启
  idleThresholdMinutes: 3,  // 3 分钟
}
```

- **独立键**，不与 `goalConfig`/`focusConfig` 捆绑 → 场景切换（覆盖写入那两个键）**不影响**本功能。
- 首次读取用 `createDefaultPresenceConfig()` 归一，缺省即上值 → 无需迁移逻辑。

## 6. 改动分层

### A. `manifest.json`
- `permissions` 增加 `"idle"`。
- `version` → `2.2.0`。

### B. `content.js`（注入所有页面）
- 新增：对页面内每个 `<video>`/`<audio>` 监听 `play` / `pause` / `ended`，维护模块级布尔 `hasActiveMedia`。
  - `play` → true；`pause` / `ended` → false。
  - 页面刚加载时扫描一次现有元素（含延迟挂载的媒体，用事件委托或 `pageshow` 兜底）。
  - 判定用 `!paused && !ended`（不查 `muted`，因为含静音豁免）。
- 新增：监听 `chrome.runtime.onMessage`，`type === "GET_MEDIA_STATE"` 时 `sendResponse({ hasActiveMedia })`。
- 现有 visibility/pageshow 逻辑不变。

### C. `background.js`
- 新增 `PRESENCE_CONFIG_KEY = "presenceConfig"` 与默认值常量。
- 新增 `createDefaultPresenceConfig(config)` 归一函数。
- 新增 `getPresenceConfig` / `setPresenceConfig`（沿用现有 storage promise 封装模式）。
- 在 `initializeExtensionState()` 增加 `ensurePresenceConfig()`（写入归一默认值）。
- 新增 `evaluatePresence()`（第 3.1 节四步）。
- 在 `evaluateBehaviorRules()` 末尾、写 `behaviorRuntime` 之后调用 `evaluatePresence()`。
- 不引入保活；每次 alarm tick 现查 idle 与媒体状态。

### D. `options.html` + `options.js`
- 在"专注/行为"设置区（`FOCUS_CONFIG_KEY` 面板下方或同面板内）新增一小块 **"空闲时暂停统计"** 设置：
  - 开关：启用"无媒体且系统空闲时暂停统计"（绑 `presenceConfig.enabled`）。
  - 下拉：空闲阈值 1 / 3 / 5 分钟（绑 `presenceConfig.idleThresholdMinutes`）。
- options.js 沿用现有 `storageGet`/`storageSet`、`createDefaultPresenceConfig` 读写与渲染模式；在 `initialize()` 读取、`savePresenceSettings()` 写回。

### E. 文档
- `CLAUDE.md`：
  - 架构图/存储键表补 `presenceConfig` 键（local，独立于场景）。
  - "行为规则"节补一句：presence 检测并入同一 1 分钟 alarm。
  - 权限若在文档列出则补 `idle`。
- 不涉及 LLM 数据内容 → `llm-privacy.md` 无需改，但按仓库"版本同步"约定，本文件的版本引用如存在则核到 v2.2。

## 7. 错误处理与边界

| 场景 | 处理 |
|------|------|
| `sendMessage` 目标 tab 不可达（关闭/导航/chrome://页） | try/catch 容错为"无媒体"，继续 idle 判断 |
| `chrome.idle` 返回 `locked`（锁屏/屏保） | 视同 idle，暂停 |
| `chrome.idle` 返回 `active` | **不**立即 resume（可能在别的程序打字）；恢复交给确定性事件 |
| 多窗口/多 tab 竞态 | 只作用于 `activeSession`，最多少计一个 tick，不污染他处 |
| SW 休眠 | 检查点挂 alarm，无需保活；状态每次现查，不跨 tick 持久化 |
| media-state 随页面重建 | content.js 内存态，新导航自动重置为无媒体 |
| 跨午夜边界 | `pauseSession` 复用 `flushSession` 自动 split |
| 已暂停 session | `!isRunning → return`，不重复处理、无乒乓 |
| 与行为规则交互 | presence 在规则评估之后执行；若暂停了 session，下个 tick 的 `addRunningSessionTimeToTotals` 自然不计暂停期，口径正确 |

### 与提醒的交互（有意的行为变化）
presence 暂停 session 后，`focusNotifications`/`distractionNotifications` 的 `pruneRuntimeMapByPrefix(sessionKey)` 会因 session 变化清掉去重记录，用户回看时可能再收到提醒。但用户是**离开电脑**，本就不该被分心提醒打扰——这是修复而非缺陷。

## 8. 兼容性

- 历史 `statsV2` **不回改**（口径：从发现时刻暂停，不回溯）。
- 存量 session 不受影响（presence 只作用于正在计时的）。
- 升级后开箱生效（`presenceConfig` 默认 enabled）；用户可在 options 关闭恢复旧行为。

## 9. 测试

### 自动化
- `node --check background.js content.js options.js`
- manifest JSON 校验
- grep 确认 `"idle"` 权限已加、`PRESENCE_CONFIG_KEY` 引用一致

### 手动清单（chrome://extensions 加载）
1. **静默暂停**：开普通网页（无媒体），不碰键盘鼠标 3 分钟 → 时长在 ~3 分钟处停增；回来滚动/点击 → 恢复。
2. **媒体豁免**：开 YouTube/B 站播放中，不动 3 分钟 → 时长继续增长。
3. **静音媒体豁免**：视频静音仍播放 → 时长继续。
4. **暂停媒体**：暂停视频 → 再静置 3 分钟 → 时长停增。
5. **切到别程序**：IDE/Word 打字 3 分钟，浏览器页在前台 → 系统不 idle，此页继续计（边界，符合预期）。
6. **锁屏** → 时长暂停；解锁回看 → 恢复。
7. **同页回看恢复**：开普通网页静置 ≥3 分钟被暂停后，**在同一页仅滚动**（不切 tab/不碰窗口）→ ~15s 内时长恢复增长。
8. **关闭开关**后重复 1 → 不再暂停（回归旧行为）。
9. **阈值下拉 1 分钟**档可加速手动回归；1/3/5 分钟可存/读。
10. 顺带回归：场景切换、目标/专注/分心通知不因本次改动异常。

## 10. 不做的事（明确边界）
- 不做常驻页面输入心跳或逐事件实时上报（页面输入仅在"页面可见 + 15s 节流"下发轻量 `PAGE_ACTIVE` 用于同页回看恢复）。
- 不做独立短周期 alarm 与回溯扣除（方案 B 已否）。
- 不改 popup（纯后台行为，在 options 管理）。
- 不把 presenceConfig 并入场景预设（独立键，避免场景切换覆盖）。
