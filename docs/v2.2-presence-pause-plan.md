# v2.2 空闲暂停计时（presence-pause）实现计划

> **For agentic workers:** 用 superpowers:subagent-driven-development 或 executing-plans 执行本计划。步骤用 `- [ ]` 追踪。

**Goal:** 当当前前台页面既不播放媒体（含静音）且用户系统空闲 ≥3 分钟时暂停计时，并在 options 提供开关与阈值。

**Architecture:** 复用既有 1 分钟 `behavior-check` alarm，在 `evaluateBehaviorRules()` 末尾加 `evaluatePresence()`：校验 session → content 页询问媒体播放态 → `chrome.idle.queryState` 查系统空闲 → 命中则 `pauseSession(now)`。媒体播放态由 content.js 维护并在收到 `GET_MEDIA_STATE` 时返回。新增独立键 `presenceConfig`（与场景解耦）。

**Tech Stack:** 纯 JS MV3 扩展，无构建/无测试框架。验证 = `node --check` + VM 沙箱逻辑单测 + 手动 Chrome 清单。

**Spec:** `docs/v2.2-presence-pause-design.md`

### Task 3: background — `evaluatePresence()` 与接入 alarm

**Files:** Modify `background.js`

需要先明确一个事实并在计划里固定下来：`evaluatePresence` 需要"媒体播放态"。询问用 `chrome.tabs.sendMessage`，但它返回 Promise 化（MV3 已支持 `return true` / Promise）。background.js 现有封装是回调 + promise 手动包（见 `tabsGet`），但没有 `sendMessage` 封装——需新增一个（风格一致、吞掉 lastError）。为保持确定性，这里给出手写版本供执行者复用。

- [ ] **Step 1**: 在 `createNotification`（~578-588）之后新增 promise 化的 `tabsSendMessage`（复用既有回调→promise 风格，无响应/报错 resolve(null) 而非 throw，方便"无媒体"容错）：

```js
function tabsSendMessage(tabId, message) {
  return new Promise((resolve) => {
    chrome.tabs.sendMessage(tabId, message, (response) => {
      if (chrome.runtime.lastError || response === undefined) {
        resolve(null);
        return;
      }
      resolve(response);
    });
  });
}
```

- [ ] **Step 2**: 新增 `getHasActiveMedia(session)`——向 session.tabId 询问；`tabsSendMessage` 已在内部吞错，若返回 `null`/无 `hasActiveMedia` 一律视为无媒体：

```js
async function getHasActiveMedia(session) {
  if (!session?.tabId) {
    return false;
  }
  const response = await tabsSendMessage(session.tabId, { type: "GET_MEDIA_STATE" });
  return Boolean(response && response.hasActiveMedia);
}
```

- [ ] **Step 3**: 新增 `querySystemIdle(thresholdSeconds)`——封装 `chrome.idle.queryState`（promise + lastError 容错），`locked` 也归入"无人看"：

```js
function querySystemIdle(thresholdSeconds) {
  return new Promise((resolve) => {
    chrome.idle.queryState(thresholdSeconds, (state) => {
      if (chrome.runtime.lastError) {
        resolve(false);
        return;
      }
      resolve(state === "idle" || state === "locked");
    });
  });
}
```

- [ ] **Step 4**: 新增 `evaluatePresence()`。逻辑：读 `presenceConfig` 与当前 `activeSession`；disabled 或 `!isRunning` 直接 return；校验 tab 仍可达且 URL 仍一致（`tabsGet` 失败 → return）；`getHasActiveMedia` → true 则 return（媒体豁免）；否则 `querySystemIdle(config.idleThresholdMinutes * 60)` → true 则 `pauseSession(now)`。

```js
async function evaluatePresence() {
  const presenceConfig = await getPresenceConfig();
  if (!presenceConfig.enabled) {
    return;
  }

  const session = await getSession();
  if (!session?.isRunning) {
    return;
  }

  let tab;
  try {
    tab = await tabsGet(session.tabId);
  } catch (error) {
    return;
  }
  if (!tab || !tab.url || tab.url !== session.url) {
    return;
  }

  const hasActiveMedia = await getHasActiveMedia(session);
  if (hasActiveMedia) {
    return;
  }

  const isIdle = await querySystemIdle(presenceConfig.idleThresholdMinutes * 60);
  if (!isIdle) {
    return;
  }

  await pauseSession(Date.now());
}
```

- [ ] **Step 5**: 在 `evaluateBehaviorRules()` 末尾、`await setBehaviorRuntime(nextRuntime);` 之后调用：

```js
  await setBehaviorRuntime(nextRuntime);

  await evaluatePresence().catch((error) => {
    console.warn("Failed to evaluate presence", error);
  });
}
```

> 注意：`evaluatePresence` 内部不依赖 `nextRuntime` 里的 session 前缀去重。执行时确认调用点在 `evaluateBehaviorRules` 函数体内最后一个 `}` 之前。

- [ ] **Step 3**: 新增 `bindMediaTracking()`——用事件委托监听 play/pause/ended，play/pause/ended 任意触发都重算；初始扫描一次；`pageshow` 时重扫（覆盖 bfcache 返回后播放态变化）：

```js
function bindMediaTracking() {
  syncMediaState();
  document.addEventListener(
    "play",
    (event) => {
      if (event.target instanceof HTMLMediaElement) syncMediaState();
    },
    true
  );
  document.addEventListener(
    "pause",
    (event) => {
      if (event.target instanceof HTMLMediaElement) syncMediaState();
    },
    true
  );
  document.addEventListener(
    "ended",
    (event) => {
      if (event.target instanceof HTMLMediaElement) syncMediaState();
    },
    true
  );
  window.addEventListener("pageshow", syncMediaState);
}
```

## 备注

- background.js / options.js 里 `createDefaultPresenceConfig` 逻辑须**保持一致**（默认 enabled、阈值回落 3、仅接受 1/3/5）。
- `evaluatePresence` 里 tab.url 校验避免"已导航走但 session 未清"时问错页。
- 媒体豁免含静音（spec 4）。
- `locked` 归入 idle（spec 3.1 step5）。
- presence 暂停会清掉 focus/distraction 的 session 前缀去重 → 用户回看可能再提醒，属预期（spec 7）。
- **已知限制（spec 接受的取舍）**：
  1. manifest content_scripts 未设 `all_frames`，仅顶层 frame 注入 content.js——若前台页在**子 iframe** 里播放媒体（如内嵌播放器），`GET_MEDIA_STATE` 会答"无媒体"，系统 idle 时该 session 会被暂停。与既有 visibility 架构一致，spec 未要求跨 frame。
  2. 先 `play()` 后被插入 DOM 的延迟挂载媒体，在插入前无事件经由 document 传播、初始扫描又未及，不会被捕获（无 MutationObserver；仅 `pageshow` 兜底）。属 spec 明示接受边界。
- 若后续要消除限制 1，可给 content_scripts 加 `"all_frames": true` 并让 background 聚合各 frame 应答——本次不做。
