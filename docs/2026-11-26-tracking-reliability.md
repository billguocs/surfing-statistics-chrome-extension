# 停留时长统计可靠性修复

## 已确认的统计口径

- 仍只统计当前聚焦窗口的活跃网页；页面隐藏、浏览器失焦或切到内部页面时结算并停止原会话。
- 保留默认 3 分钟空闲阈值和每分钟检查，从发现空闲的时刻暂停，不回扣此前已计入时间。
- 最近一次结算点至当前时刻的间隔 **大于 2 分钟** 时，整段未确认区间不计入；恰好 2 分钟仍可计入。后台结算、弹窗实时显示和目标统计使用相同规则。
- 跳过区间时仍推进持久化 checkpoint，重试不会把该区间重新计入。下次检查只统计新的短区间；运行会话在检查到中断后重置提醒起点。
- 这是避免休眠多计的保守策略，不能准确区分系统休眠和 Chrome 长时间卡顿；后者也可能造成少计。

## iframe 媒体和交互

内容脚本注入所有匹配的 frame，包括可匹配父页面的 about:blank frame。只有顶层文档发送整页可见性消息；子 frame 的导航、隐藏和出现不会暂停或替换整页会话。

后台在系统空闲时向标签页所有 frame 广播媒体查询。由于 `tabs.sendMessage` 只返回一个响应，每个播放媒体的 frame 额外发送带查询 ID 的正向结果。后台最多等待 500 毫秒，任意 frame 报告播放中即获得豁免；静音播放仍符合原先豁免口径。查询无响应时仍按无媒体处理。

可见 frame 内受信任的点击、滚轮、键盘和触摸输入沿用 15 秒节流，可恢复对应前台标签页的空闲暂停会话。后台重新验证窗口焦点、顶层 URL、标签页 ID 和可用的文档生命周期；子 frame 的 documentId 不会覆盖顶层文档身份。

## 弹窗刷新

加载报表期间出现会话变更时标记需要补刷。最新请求成功后合并这些变更并读取新快照，再开始渲染和轮询。旧请求不能消费新请求的待刷新标记；请求失败时结束补刷链，后续用户操作或会话事件仍可恢复读取，避免自动重试循环。

## ISO 周历史修复

首次导入旧 local 数据和已完成 IndexedDB 迁移的数据库均执行一次周报修复，数据和完成标记在同一读写事务提交。

- 从有效的日报日期重建 ISO 周桶，日报本身不变。
- 先抵扣原周桶中同 ISO 周、同站点的已覆盖时长，再抵扣该站点其他旧周桶中已由日报覆盖的时长，避免旧算法错周造成重复累计。
- 无日报明细可对应的剩余时长保留在原周键下。其准确日期已经缺失，无法可靠重分周；不推测补造日期。
- 修复前的周桶以包含独立站点元数据的快照保存在 IndexedDB meta 的 `weeklyBeforeIsoRepair`，以便核查或恢复。修复完成标记为 `isoWeekRepairVersion`。
- 按新周桶更新站点元数据引用计数，失败回滚后可重新执行；后续启动跳过已完成修复。
- 清空统计时一并删除修复备份，避免清空后保留历史数据。

## 验证

`node --test tests/regressions.test.cjs` 为统一回归入口，加载计时存储、frame 和弹窗刷新测试模块。覆盖 2 分钟边界、跨日跨周、8 小时中断、worker 重载、重复结算、迁移幂等、已有数据库修复、事务回滚、历史残余时长、iframe 媒体信号与交互守卫、弹窗并发请求和失败恢复。

另使用隔离的无头 Chrome 验证真实 IndexedDB 的 ISO 周重建、历史残余保留、迁移幂等、长间隔排除、恢复后重复结算和清空。实际加载扩展后还验证了跨域 iframe 音频播放豁免、停止媒体后暂停、iframe 内受信任点击恢复、顶层文档身份保留、原生标签切换、内部页面排除和关闭标签后的恢复。该验证模拟了 idle API 返回值，未实际等待系统空闲或让电脑休眠。

真实扩展手动验收步骤：

1. 重新加载扩展并刷新测试网页，交替访问两个 HTTP(S) 标签页和 `chrome://settings/`，确认只统计当前前台网页。
2. 切到其他应用后再返回，确认失焦期间不计入。
3. 在跨域 iframe 内播放音视频，保持系统空闲超过所设阈值，确认仍计时；暂停媒体后等到空闲检查，确认停止。
4. 只点击或滚动 iframe，确认从空闲暂停恢复；隐藏或导航一个子 frame 不影响整页计时。
5. 普通网页计时后让电脑休眠数分钟再唤醒，确认日报、周报及弹窗不会增加整段休眠时间，随后正常计时。
6. 网页重新加载时打开弹窗，确认页面恢复计时后弹窗也会更新，不需要关闭重开。
